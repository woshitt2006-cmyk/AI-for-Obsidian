# 当前成果总结

整理日期：2026-10-14。项目从理念设计发展到本地 Bridge MVP，尚未完成真实用户独立操作的完整验收，也未开发 Obsidian 插件。

## 我们已经完成什么

1. 明确学习目标：让 AI 帮助建立知识连接，并通过节点追问继续探索。ChatGPT 负责解释，Bridge 负责文件处理，Obsidian 负责持久存储与浏览；Codex 是开发工具，不是每次导入必需的运行时。
2. 设计并实验结构化图协议：稳定 ID、节点类型、关系方向、增量批次、身份冲突和候选状态。
3. 以相场断裂长度尺度为例完成多轮节点与关系生成。扩展到网格、离散误差、AT1/AT2、形函数和有限元插值，形成 13 节点/16 候选关系的示例图。
4. 根据使用反馈，把短摘要升级成节点完整 `content_md` 与关系完整 `detail_md`。节点含公式、符号、机制、例子和边界，关系以单独笔记解释为什么相连。
5. 实现本地导入 MVP：合法性校验、预览、增量合并、Markdown/Canvas 输出、重复导入保护、备份与普通异常回滚。
6. 实现本地追问基础：读取节点、一跳入边/出边、邻居摘要和人工记录，输出带已有 ID 清单与 v1.1 规则的提示词。
7. 增加 Windows 文件选择窗口，使用户可以自行导入和生成追问，不必每次把 JSON 发给开发者。
8. 准备可协作仓库：源码、示例、协议结构、测试、CI、贡献规范与 MIT 许可。

## 关键实验发现

- 短 description 只适合地图摘要，不足以支撑学习。完整正文应直接由 AI 提供，导入器负责保存，不凭摘要猜测知识。
- 相同 ID 的短回答不能直接覆盖已有长文。因此当前采取追加方式；矛盾需要人工审阅。
- foundation/application/extension 等标签无法精确覆盖所有“控制、影响、具体形式、极限”关系。保持 v1.1 枚举兼容，缺口留在待审阅记录，下一版本单独讨论。
- AI 可能漏必填字段、反转边方向、遗漏数值例子或坐标变换。格式校验无法代替内容审阅。
- Obsidian 偶尔尚未索引外部新增笔记，会显示“未找到”；必须先确认路径和文件是否存在，再刷新索引。
- 用户反馈认可示例学习与地图体验，但尚没有对照实验或量化证据证明学习效果。

## 验证与实际边界

既有 13 项测试覆盖合法输入、预览、幂等、增量保留、冲突、事务回滚、预览竞态、对称关系、反向关系、追问上下文和示例兼容。发布整理新增示例文件链接、结构、协议和路径检查。最新本地结果见 [VALIDATION.md](VALIDATION.md)。

本机测试不等于 Linux 或其他 Python 版本已测试；CI 矩阵只有配置，远端结果上传后确认。PowerShell 脚本语法与 Windows Forms 可用性已检查，但完整 GUI 与 Obsidian 阅读流程还需人工验收。

## 下一步最小验收
